## 任务目标

在 wxnode 与 uni-ui 中建立“科目 -> 题库集 -> 章节/题目”的清晰层级，新增真题独立存储结构与成绩统计，补齐专项/随机练习的数据与接口设计，并支持在 wxbackground 后台配置科目与章节名称，保证小程序前端逐题加载且接口性能可控。

---

## 背景分析

### 现状
- 数据表已包含 `question_banks`/`question_chapters`/`questions`/`user_study_progress`，章节由解析标签 `tags[0]` 生成；无“科目”维度。
- 现有 API 以题库集和章节为中心，`/questions/banks` 和 `/question-banks/:bankId/chapters/:chapterId/questions` 支持分页与逐题拉取。
- 前端仅“模拟考试”进入题库集列表，真题/专项/随机尚未接入实际数据流。

### 问题/需求
- 需要按科目筛选题库集，且科目下含多个来源题库集。
- 真题练习必须独立成套试题结构，不能复用章节题库。
- 科目列表需要在 wxbackground 后台可配置，章节名称以 gemini 题库为准并允许后台修改。
- 专项训练需聚合同科目下所有题库集的同章节题目。
- 随机练习需在科目下跨题库抽题，且避免大数据全量返回。
- 真题练习不保存进度，但需要记录准确率、答题正确/失败，并支持查看错题。
- 专项需要展示百分比，随机不展示百分比。

### 影响范围
- 后端：数据库结构、题库/章节/进度服务、API 文档。
- 后台：wxbackground 管理端的科目与章节命名配置界面。
- 前端：题库入口页、题库集列表、答题页与新练习入口页。

## 实现方案

### 技术选型
- 继续使用现有 Node.js + TypeScript + Express + MySQL + Redis 架构。
- wxbackground (Next.js) 作为管理端，新增科目与章节命名配置入口。
- 章节聚合采用“科目章节映射”或严格章节命名规范，避免专项训练跨库混乱。
- 随机抽题采用预计算随机键或 id 采样策略，规避 `ORDER BY RAND()` 的全表扫描。
