# 配套思路文档：AIGC多媒体创作平台质量管理

## 1. 八段式总纲
- **摘要**：背景（AIGC平台）+ 9人团队/11个月 + 3大过程落地 + 成果（通过率99.5%/满意度4.8）。
- **项目概述**：介绍6大原子能力，明确PM职责与质量挑战（主观性/技术复杂/外部依赖）。
- **方法论框架**：PMBOK7“测量”绩效域 + 质量管理作为MMA落地 + 裁剪点（人机协同评审）。
- **规划质量管理**：建立分层评价体系（技术指标+业务主观评分）。
- **管理质量**：过程管控（QA）+ 代码审查/SonarQube + Prompt版本控制。
- **控制质量**：结果检查（QC）+ 鱼骨图分析“画面崩坏”根因 + 帕累托图分析缺陷分布。
- **总结**：成功上线，反思弱网测试不足。

## 4. 亮点清单
1.  **AIGC质量评价难题的破解**：提出“主客观结合”的评价体系，切中行业痛点。
2.  **工具链的应用**：SonarQube、GitLab CI/CD、Prompt版本库，体现技术专业性。
3.  **质量工具的组合拳**：鱼骨图找根因，帕累托图找重点，TDD做预防。
4.  **具体的Bug案例**：“水墨风”画面崩坏、Suno接口超时，真实感强。
5.  **过程改进的闭环**：发现问题 -> 解决问题 -> 沉淀最佳实践（输入标准化）。
6.  **Prompt工程的质量管理**：将Prompt视为代码进行版本控制和A/B测试。
7.  **PMBOK7原则**：关注质量、裁剪等原则的落地。
8.  **数据口径**：TP99、覆盖率80%、评分4.0等量化指标。
9.  **测试左移**：在管理质量阶段就介入代码审查，而不是等到控制质量阶段才测。
10. **用户视角的反思**：弱网环境下的体验问题，体现以用户为中心。

## 5. 关键术语/工件清单
- **QA (Quality Assurance)**：质量保证
- **QC (Quality Control)**：质量控制
- **TDD (Test-Driven Development)**：测试驱动开发
- **CI/CD**：持续集成/持续交付
- **SonarQube**：代码扫描工具
- **鱼骨图 (Fishbone Diagram)** / **因果图**
- **帕累托图 (Pareto Chart)**
- **TP99**：99%请求的响应时间
- **根因分析 (RCA)**

## 6. 高频扣分点规避
- **规避1**：QA与QC混淆。**对策**：管理质量写过程（QA），控制质量写结果（QC）。
- **规避2**：质量标准空洞。**对策**：列出了具体的响应时间（3s）和主观评分（4.0）。
- **规避3**：缺乏预防措施。**对策**：强调了代码审查和TDD的作用。
- **规避4**：工具使用生硬。**对策**：鱼骨图和帕累托图都结合了具体案例分析。
- **规避5**：忽视AIGC特性。**对策**：专门提到了Prompt的版本管理和效果评分。
